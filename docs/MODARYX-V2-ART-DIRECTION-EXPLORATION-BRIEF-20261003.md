# MODARYX V2 — Brief d'exploration de direction artistique

**Date : 2026-10-03**
**Statut : TERMINÉ — préparation uniquement / HIGH-FI TOUJOURS BLOQUÉ**

Ce document prépare la phase artistique future. Il ne choisit aucune direction finale et ne constitue aucune validation visuelle.

## 1. Principe directeur

> L'univers est le théâtre ; le modding est l'action.

La marque doit pouvoir être immédiatement reconnue comme MODARYX, mais la fonction produit reste prioritaire :

- jeu ;
- recherche ;
- contenu ;
- compatibilité ;
- dépendances ;
- installation ;
- créateur ;
- collection.

## 2. Qualité recherchée

La cible n'est pas “plus d'effets”.

La cible est une sensation :
- premium ;
- précise ;
- dense mais lisible ;
- rapide ;
- crédible ;
- vivante ;
- distinctive ;
- cohérente desktop/mobile.

## 3. Axes à explorer plus tard

### Axe A — Forge éditoriale

Caractère :
- surfaces sombres maîtrisées ;
- hiérarchie nette ;
- accent sur contenu, compatibilité et release ;
- détails de matière très discrets ;
- identité monde/forge utilisée en arrière-plan.

Question à tester :
MODARYX paraît-il premium sans ressembler à un launcher générique ?

### Axe B — Monde vivant contrôlé

Caractère :
- ambiance locale/heure/saison perceptible ;
- hero et transitions plus immersifs ;
- compagnons/monde présents comme signatures secondaires ;
- contenu fonctionnel toujours au premier plan.

Question à tester :
l'univers enrichit-il la découverte sans ralentir ni distraire ?

### Axe C — Atelier technique premium

Caractère :
- précision informationnelle ;
- status chips ;
- provenance ;
- compatibilité ;
- versioning ;
- installation ;
- Creator Studio très structuré.

Question à tester :
la plateforme inspire-t-elle confiance tout en conservant une identité émotionnelle ?

Ces axes peuvent être hybridés après tests. Aucun n'est déclaré gagnant.

## 4. Invariants visuels

Toutes les explorations doivent préserver :

- contraste lisible ;
- focus clair ;
- texte produit prioritaire ;
- densité progressive ;
- états visibles sans couleur seule ;
- mobile conçu spécifiquement ;
- reduced motion ;
- media avec dimensions réservées ;
- aucun décor bloquant le LCP ;
- aucun effet obligatoire pour comprendre une action.

## 5. Typographie

La typographie finale doit distinguer :

### Interface
- lecture rapide ;
- tableaux/filtres/métadonnées ;
- petits labels lisibles ;
- chiffres/versioning stables.

### Expression de marque
- titres/hero ponctuels ;
- pas de fonte décorative sur les informations critiques ;
- fallback métriquement proche.

Aucune famille finale n'est choisie ici.

## 6. Surfaces

Prévoir des niveaux sémantiques, pas des cartes partout :

- base/background ;
- surface primaire ;
- surface élevée ;
- surface interactive ;
- surface decision/installation ;
- surface trust/provenance ;
- overlay/drawer ;
- modal critique.

Chaque niveau doit avoir une fonction identifiable.

## 7. Couleur

Le high-fi devra définir des couleurs sémantiques séparées de la marque :

- texte primaire/secondaire ;
- bordure ;
- focus ;
- success ;
- warning ;
- danger ;
- incompatible ;
- unverified ;
- information ;
- accent de marque.

La météo/saison ne peut pas modifier la sémantique des statuts.

## 8. Cartes de contenu

Une ContentCard premium doit rester compréhensible en moins de quelques secondes :

- jeu/context ;
- nom ;
- type ;
- creator ;
- compatibilité ;
- version ou fraîcheur ;
- trust/distribution state si nécessaire ;
- action secondaire claire.

Pas de surcharge lore.

## 9. Fiche contenu

La zone décisionnelle doit concentrer :

- release active ;
- game/version/platform ;
- compatible/incompatible/unverified ;
- dependencies/conflicts ;
- install/download capability ;
- provenance essentielle.

Le média/hero ne doit pas repousser ces éléments trop bas.

## 10. Search / catalogue

La sophistication visuelle doit servir :

- scanning ;
- filtres actifs ;
- tri ;
- comparaison ;
- compatibilité.

Éviter les filtres décoratifs difficiles à lire.

## 11. Creator Studio

L'identité artistique doit devenir plus sobre et productive :

- structure ;
- progression ;
- erreurs ;
- validation ;
- rights/provenance ;
- files/releases.

Le studio n'est pas un hero marketing.

## 12. Community

La communauté doit visuellement distinguer :

- discussion ;
- review ;
- support ;
- signalement ;
- modération ;
- creator/team.

Éviter un feed social générique qui détourne du modding.

## 13. Univers vivant

L'adaptation réelle heure/saison/météo peut agir sur :

- lumière ;
- ambiance de fond ;
- intensité décorative ;
- particules légères ;
- détails environnementaux.

Elle ne doit pas agir sur :

- couleurs de statut ;
- lisibilité ;
- ordre de navigation ;
- tailles de composants ;
- emplacement des actions critiques.

## 14. Motion

Motion autorisée si elle :

- clarifie un changement d'état ;
- aide à suivre la navigation ;
- renforce subtilement la marque.

Motion à éviter :

- animation permanente ;
- parallaxe lourde ;
- mouvement derrière texte critique ;
- transitions longues sur actions répétées.

## 15. Compagnons / loup / dragon

Les assets existants restent des **candidats**.

Avant usage final, tester :

- qualité d'intégration ;
- cohérence de style ;
- poids visuel ;
- performance ;
- mobile ;
- reduced motion ;
- risque d'éclipser le produit.

Aucun asset existant n'est approuvé automatiquement.

## 16. Méthode de comparaison high-fi future

Créer plusieurs concepts comparables sur les mêmes surfaces :

- Home ;
- Game Hub ;
- Catalog ;
- Content Detail ;
- Mobile Game Hub.

Comparer sans classement automatique sur :

- clarté immédiate ;
- hiérarchie ;
- confiance ;
- densité ;
- personnalité ;
- cohérence ;
- mobile ;
- performance perçue ;
- accessibilité de conception.

La sélection finale doit être humaine.

## 17. Interdictions

Ne pas :
- recopier Nexus/CurseForge/Modrinth visuellement ;
- reprendre la cascade CSS V1 ;
- réintroduire Nova Forge dans la marque ;
- confondre “cinématique” avec qualité ;
- utiliser de faux compteurs pour remplir le design ;
- choisir un concept uniquement parce qu'il est spectaculaire.
