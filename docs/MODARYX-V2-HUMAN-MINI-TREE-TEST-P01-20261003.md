# MODARYX V2 — Mini tree test humain — Participant réel 01

**Date : 2026-10-03**  
**Statut : TERMINÉ pour ce participant — validation humaine globale EN COURS**

## 1. Profil

Participant réel, non présenté comme expert du modding.

Ce test court a porté sur 5 points critiques de l'architecture d'information et de la terminologie.

## 2. Réponses observées

### Q1 — Retrouver une configuration précise de jeu

Scénario :
retrouver une configuration contenant les mods utilisés et leurs versions précises.

Premier réflexe observé :
- chercher d'abord le jeu ;
- entrer ensuite dans ses mods/plugins.

Lecture :
- le participant ne pense pas spontanément à **Bibliothèque → Profils de jeu** ;
- le concept de profil/configuration personnelle n'est donc pas encore naturellement trouvable ;
- le contexte **jeu** est le point d'entrée dominant.

**État : AMBIGUÏTÉ RÉELLE DÉTECTÉE**

### Q2 — Retrouver un contenu plus tard

Premier réflexe observé :
- **Favoris** ;
- idéalement contextualisés par plateforme/jeu ;
- action attendue de type **Ajouter aux favoris** ou **Ajouter pour plus tard**.

Lecture :
- le concept Favori est compris naturellement ;
- le contexte jeu reste important.

**État : COMPRÉHENSION CLAIRE**

### Q3 — Partager une sélection thématique

Premier réflexe observé :
- notion de **Mes recommandations** ;
- ou dossier partageable regroupant plusieurs mods ;
- association possible avec des mods déjà installés.

Lecture :
- le besoin de partage est compris ;
- le mot **Collection** n'est pas apparu spontanément ;
- une confusion reste possible entre recommandation éditoriale, dossier partagé et configuration installée.

**État : AMBIGUÏTÉ RÉELLE DÉTECTÉE — Collection / recommandation / profil**

### Q4 — Dépendances et conflits

Attente spontanée :
- MODARYX doit prévenir automatiquement l'utilisateur ;
- exemple mental : avertissement clair avant installation si un mod entre en conflit avec un autre mod/plugin.

Lecture :
- ne pas exiger que l'utilisateur cherche manuellement une rubrique technique ;
- compatibilité, dépendances et conflits doivent être **proactifs et visibles au moment de la décision** ;
- une page détaillée peut exister, mais l'information critique doit remonter avant installation.

**État : ATTENTE UX FORTE CONFIRMÉE**

### Q5 — “Catalogue consultable”

Compréhension spontanée :
- voir et parcourir les contenus ;
- ouvrir leurs pages ;
- consulter caractéristiques et informations ;
- **pas** télécharger automatiquement.

Lecture :
- la formulation **Catalogue consultable** distingue correctement catalogue et distribution pour ce participant.

**État : COMPRÉHENSION CLAIRE**

## 3. Corrections / renforcements issus d'une vraie réponse humaine

### A. Profils de jeu

Le chemin actuel **Bibliothèque → Profils de jeu** ne doit pas être le seul moyen de retrouver une configuration.

À renforcer dans la conception :
- depuis un Game Hub, accès visible à **Mes profils pour ce jeu** ;
- depuis la Bibliothèque, conserver **Profils de jeu** comme vue transversale ;
- éviter d'obliger l'utilisateur à comprendre d'abord le concept abstrait de Bibliothèque.

### B. Collections

Le terme **Collection** seul n'est pas suffisant pour exprimer spontanément “sélection recommandée à partager”.

À renforcer :
- microcopy du type **Sélections de mods à organiser et partager** ;
- distinguer visuellement Collection d'un Profil de jeu installé ;
- possibilité d'utiliser “Recommandations” en microcopy secondaire, pas comme nouveau type de domaine sans décision explicite.

### C. Conflits / prérequis

À afficher proactivement :
- incompatibilité majeure ;
- dépendance obligatoire ;
- version requise ;
- avertissement avant installation/téléchargement lorsque pertinent.

Ne pas enfouir ces informations uniquement dans **Compatibilité et prérequis**.

## 4. Résumé

Points confirmés humainement pour ce participant :
- Favoris ;
- sens de **Catalogue consultable** ;
- attente d'avertissements automatiques sur conflits/prérequis.

Points nécessitant amélioration :
- trouvabilité des **Profils de jeu** ;
- compréhension/nommage des **Collections**.

## 5. Limite de preuve

Ce document représente **un participant réel**.

Il ne permet pas de conclure que tous les utilisateurs comprennent l'architecture de la même manière.

État global recommandé :
- preuve humaine : **OBTENUE pour 1 participant réel** ;
- validation humaine globale : **EN COURS** ;
- besoin utile suivant : comparer avec des profils indépendants issus de recherche/Work et, idéalement, d'autres personnes réelles.
