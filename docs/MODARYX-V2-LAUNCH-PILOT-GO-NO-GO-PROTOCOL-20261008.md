# MODARYX V2 — protocole pilote lancement / go-no-go — 2026-10-08

**État : EN COURS — aucun lancement commercial autorisé par ce document**

Le modèle KPI dit **quoi mesurer**. Ce protocole définit **dans quel ordre apprendre** avant de décider de lancer ou monétiser.

## 1. Phase problème / valeur

Avant acquisition payante :
- entretiens utilisateurs qualifiés ;
- tâches réelles de découverte, compatibilité, collections/profils, création ;
- compréhension du vocabulaire ;
- raisons d'abandon ;
- attentes confiance/privacy/accessibilité.

Candidat : 12–20 entretiens, déjà cohérent avec le protocole pricing.

État : **EN COURS**.

## 2. Recherche pricing

Utiliser les stimuli existants uniquement comme recherche :
- 4,99 €
- 6,99 €
- 8,99 €

Aucune carte bancaire, fausse commande ou faux abonnement.

État : **EN COURS / terrain PREUVE MANQUANTE**.

## 3. Pilote gratuit utile

Objectif : prouver qu'un MODARYX gratuit apporte une vraie valeur.

Activation candidate :
> accomplir un workflow utile complet, pas seulement créer un compte.

Exemples :
- trouver un contenu pertinent puis comprendre compatibilité/dépendances/provenance ;
- construire une collection/profil utile ;
- créateur : terminer un workflow de brouillon/publication réellement utile.

Mesurer :
- activation ;
- D1/D7/D30 ;
- workflows complétés ;
- abandon ;
- support ;
- modération ;
- incidents ;
- coût infra/provider ;
- retours qualitatifs.

Aucun Premium ne doit être nécessaire pour rendre ce pilote utile.

## 4. Acquisition

Tester séparément :
- organique contenu/recherche ;
- communautés/créateurs avec permission ;
- canaux owned ;
- referral ;
- acquisition payante plus tard seulement.

Interdits :
- spam ;
- faux avis ;
- faux compteurs ;
- fausse rareté ;
- influence non divulguée ;
- paid acquisition avant modèle d'attribution/privacy/coût crédible.

CAC réel : **PREUVE MANQUANTE**.

## 5. Pilote commercial contrôlé

**BLOQUÉ** tant que ne sont pas prêts :
- vendeur/opérateur ;
- territoires ;
- taxes/facturation ;
- paiement/refunds ;
- CGV/mentions/privacy ;
- droits/licences ;
- accessibilité applicable ;
- support/fraude ;
- production technique ;
- décision explicite propriétaire.

Aucun « test paiement » réel ne doit précéder ces gates.

## 6. Go / no-go

Ne pas choisir des seuils arbitraires aujourd'hui.

La décision devra se baser sur :
- valeur utilisateur ;
- activation ;
- rétention ;
- qualité/stabilité ;
- support/modération ;
- incidents/fraude ;
- privacy/accessibilité ;
- droits/juridique ;
- coûts réels ;
- conversion/churn si vente ;
- capacité opérationnelle.

Règles :
- signup ≠ activation ;
- intention de payer ≠ conversion ;
- payment-net ≠ bénéfice ;
- forte conversion ne compense pas une non-conformité ;
- gate technique verte ≠ gate commerciale/légale verte.

## 7. Reçu de pilote

Chaque pilote doit enregistrer :
- commit/environnement ;
- période ;
- participants/segments ;
- canaux ;
- définition activation ;
- activation/rétention ;
- support/modération/incidents ;
- coûts ;
- écarts privacy/legal ;
- feedback ;
- décision + propriétaire + justification.

Minimiser les données personnelles.

## 8. Conditions avant décision commerciale

Toujours **PREUVE MANQUANTE** :
- gratuit utile terrain ;
- activation/rétention ;
- valeur Premium récurrente ;
- willingness-to-pay terrain ;
- coûts support/modération/infra/providers ;
- CAC ;
- conversion/churn ;
- seller/taxes/payment/refunds ;
- droits/licences ;
- legal/privacy/accessibility readiness ;
- décision propriétaire.

Aucun prix ou lancement n'est rendu canonique par ce document.
